### Build is a live scan — the layer stack on every Build step (foundation slice)
Build produced a pack in Discover's language and never showed it: forms plus a checklist rail, while Discover draws every pack as L1 … GOV slabs and artefact cards. The centre stage of every Build step is now the layer stack of the pack being compiled (`docs/BUILD_JOURNEY.md`, "The scan: Build renders the layer model" — the principles and the three slices; this is the first):
- **The artefacts are the adapter's.** `POST /api/library/instantiate` also returns `adapted` — `adapt()` of the env-overlaid canonical, exactly as `POST /api/validate` computes it (the smoke test asserts the two byte-identical for the same canonical; the captured fixture carries the field and its stability test compares it against a fresh in-process adapt). The stack draws that projection with the same `.card` markup Discover uses: the card body is one shared helper, `studio/card-html.mjs` `artefactCardHtml`, that Discover's `renderCard` and the stack both call (the stateful shell — active card, unresolved references, the benchmark action — stayed in `renderCard`; only the pure HTML moved), so what Build shows on COMPILE is the artefact list Discover shows after the hand-off, id for id. A Scaffold card is dashed in both views.
- **The model** (`studio/build-model.mjs` `buildStackModel({ adapted, checklist, requirements, candidates, todos, params, mode, toggles, expanded })`, pure, under `node:test`): the slabs in `LAYER_DEFS` order (L2X only with an artefact or a clause, GOV neutral, L4 with its policy · alerting · self-healing subgroups), each slab's edge state from the clause checklist of its dimension (fail > pending > placeholder > pass, with the clause and why), its maturity as clause counts with pass-on-placeholder its own segment, ghost cards for the rubric (every clause of the tier on DEFINE — the silhouette; a clause still unmet afterwards, as *Missing*, Discover's word), the selection's SLI and SLO candidates on L1, the todos pinned to the slab of their path family and to the Scaffold card the adapter minted for them (the engine's symbols and the adapter's ids agree: 21 todos, 21 Scaffold cards, the same set), a section switched off dimming the slab it feeds, and the detail artefacts Discover folds (panels, queries) folded here too.
- **The view** (`studio/build-stack-view.mjs` `renderBuildStack` / `buildStackHtml` + `wireBuildStack`): Discover's `.section` / `.section-head` / `.section-grid` markup and layer tokens, a verdict edge per slab, a click on the slab head opens the layer's clauses, the theme tokens only so light and dark both follow. **DEFINE** draws the silhouette under the library entries, reshaping live with the tier and the entries, the edges lighting up as soon as the selection compiles. **COMPILE**'s canvas is the live stack — the SLI rows and the section toggles stay as the control area above it, the warnings and the schema verdict between, the YAML as a collapsible below; untick an SLI and L1 loses its card and its SLO, switch dashboards off and L3 dims, its clauses turn red on the edge and come back as ghost cards. **VERIFY** draws the stack with the todos on their slabs (the inline parameter inputs unchanged; a pin on the card each names scrolls to it) and adds the per-layer maturity bars to the conformance card; the verdict cards, the artefacts strip and *Ready to continue?* are otherwise unchanged. The clause rail is a compact summary — status, the three counts, the failing clauses always listed, how many pass only on a placeholder, the full list under "all clauses" — since the per-layer clauses now live on the slabs. Two never-persisted UI fields on the draft (`stackOpen`, `railOpen`) keep an opened layer open across the debounced re-instantiation.
- **Tests**: `tools/test-build-model.mjs` (slab order and L2X gating, edge states incl. the dashboards-off red edge and the cold all-pending silhouette, the silhouette across the three tiers with the rubric's labels, the L1 candidates, todo pinning per family and per card, L4 subgroups, maturity counts, dimming, a headless render of the stack and of the compact rail, `artefactCardHtml` as the one card body, the artefact list deep-equal to the adapter's for the same canonical); `server/test-smoke.mjs` (the `adapted` field and its identity with `/api/validate`).

### The BUILD journey, slice 1: the pack library, the tier scaffold and `packc init`
A second journey beside Discover · Diagnose · Remediate, for teams that have no pack yet — Define (what are we observing?) · Compile (what should we watch?) · Verify (is it ready to use?), handing the produced pack to Discover. This slice is the engine with no UI (`docs/BUILD_JOURNEY.md` is the contract slice 2's studio and API build on):
- **The library is data** (`library/products/*.library.yaml`, `library/archetypes/*.library.yaml`, format `library: v1`; `library/README.md`): one versioned entry per product or archetype — SLI templates with metric names, PromQL, `minTier`, per-tier SLO objectives and a burn profile, params (`${id}`), scrape jobs, product boards, derived views, synthetic probes, chaos and remediation templates, and an evidence block per entry and per SLI (`recorded-live | reference-pack | upstream-docs | semconv`, sources, notes, gaps). Ten entries: kafka, prometheus, grafana (derived from the reference packs, measured live 2026-09-22), ibm-mq (the certified pack of mq-observability-pack, 2026-09-16), alertmanager and otel-collector (the stack self-metric alias table, pinned stack 2026-09-07), loki and tempo (`up` of the lab's scrape job plus the collector / promtail rows — no `loki_*` / `tempo_*` request metric is in the evidence, so none is named), http-service and queue-consumer (OTel semconv v1.27.0 in Prometheus spelling, marked not verified live). `validateLibraryEntry` refuses an undeclared `${param}`, a listed metric name that does not appear in the query, and an entry without a ratio SLI at tier-3 or a threshold SLI by tier-2.
- **One tier scaffold** (`tools/lib/library.mjs` `tierScaffold`, shared by every entry) produces the structural sections a tier needs — otel, backends, pipelines, storage, recording rules, the overview / burn / deployment-overlay / customer-impact boards, burn-rate policy from named profiles (severities demoted at tier-3), routes, remediation, baselines, probes, chaos — sized so that every MUST clause of `tools/lib/conformance.mjs` applying at the tier passes with every toggle on; `tierRequirements(tier)` is that rubric filtered by `minTier`, not a second rubric. Toggles (`slos`, `policy`, `routes`, `dashboards`, `validation`, the SLI list) leave honest gaps: a section off is absent and both the schema and the rubric say so. A remediation is triggered by its SLI's fast burn alert under the compiler's name (`alert:<slo>_burn_<factor>x_<short>_<long>`), the alerts a library pack compiles — the entries carry no `trigger` (the reference packs' symptom-alert names resolved only where those repos ship rule files; in a library pack 0 of 21 did) and the suite asserts every trigger and every chaos `expected_alert` against the compiled rules.
- **Placeholders and provenance.** Values the library cannot know are params flagged `placeholder: true`; left at their default they land in the pack as a plausible value AND as a todo `{ path, fields, what, clauses, params }` and the annotation `library.todo.<artefact symbol>` — the crawler's `crawler.scaffold.<symbol>` convention — and `tools/lib/adapter.mjs` now lists `library.todo.` among its scaffold prefixes, so the studio parks a placeholder artefact as Scaffold like a crawler stub. The backend versions the pack declares (`telemetry.backends[].version.declared`, `storage.<signal>.version`) are placeholder params too — `prometheus_version`, `loki_version`, `tempo_version` — with `min` the scaffold's floor, so a team is told to state what it runs before tier-1's `gating: enforce` applies. Every produced pack carries `library.source = <entry>@<version>`, `library.tier`, `library.toggles`, `library.slis`, `library.params`, per-SLI `library.evidence.slis.<id>` and `metadata.labels.source: library`.
- **Engine API** (pure, browser-safe, served at `/lib`): `parseLibraryEntry`, `validateLibraryEntry`, `libraryIndex`, `tierRequirements`, `defaultToggles`, `instantiatePack(entry | entries, { name, tier, environment, owners, params, toggles })` → `{ canonical, todos, provenance, warnings }` (several entries compose into one pack, ids prefixed, params namespaced `<entry>.<param>`; an unknown param key or a non-scalar value is an error that lists the known keys, never a silent drop; a selected SLI above the tier is excluded with a `sli-excluded` warning, not fatal, so a tier change after the SLIs were ticked keeps the rest), `validationSummary`, `symbolOf`. Node side: `server/library.mjs` `loadLibrary({ root })` → `{ entries, errors }` (a missing root is an error naming it, not an empty library), and `library/` is in the package's `files` so an installed `packc init` has its entries.
- **`packc init`** (`tools/pack-init.mjs`): `--list`, `--show <entry>`, `--entry <id>[,<id>] --tier <tier> --name <svc> [--env] [--owner]... [--param k=v]... [--slis a,b] [--no-<section>] [--out] [--json]`; YAML to stdout, todos, warnings and the conformance line to stderr; exit 0 · 1 (the pack does not validate against the schema or fails a MUST clause of its tier, so a CI caller can tell MUST 14/15 from 15/15) · 2 (usage), the convention of validate-pack and journey. A `--param` value carrying a double quote, a backslash or a control character is refused (it is spliced verbatim into label matchers), and every SLI expression is parsed with the Lezer grammar once the values are in — a failure is `warning [promql]` and exit 1; `instantiatePack` takes the parser as `promql` (the engine stays browser-safe) and returns `warnings: [{ kind, message, sli?, field? }]`, which also carries the burn-rule generator's own warnings on the produced policy (kind `burn-rules`, compiled once at build time) — and the prometheus entry's four subtracted good legs now carry the `(… or vector(0))` guard the generator asks for, with `== bool` on the up comparison, stated in its evidence notes (the reference pack's forms are unguarded; upstream fix pending).
- **Proof** (`tools/test-library.mjs`, in `npm test`; `npm run lint:library`): every entry × every tier with default toggles validates against the v1.2 schema, compiles through every `compile.mjs` target, builds its boards with `checkBindings` green, passes every applicable MUST (the failing set is asserted ⊆ the clauses the todos name, and empty) and every SHOULD at tier-1, carries the provenance annotations, and its todos are exactly the `library.todo.*` annotations; dashboards off fails exactly the dashboard clauses and policy off exactly the burn-rate clause; the adapter projects the placeholders as Scaffold; composition, SLI selection, param overrides and the CLI's exit codes are pinned; three goldens (`tools/fixtures/library/kafka.tier-2`, `ibm-mq.tier-1`, `http-service.tier-3`) are byte-stable (`node tools/test-library.mjs --update`).
### Build number: the commit the studio runs from, in the footer, the CLI and /api/version
"v0.4.0" in the footer said nothing about *which* 0.4.0 was running. There is no build step, so the identity of a process is its commit, read once by one module.
- **`server/build-info.mjs`** — `buildInfo({ root, refresh })` → `{ version, build, commit, branch, dirty, date, shallow, source }`: version from package.json; from git, `build` = `rev-list --count HEAD` (an integer that climbs with every commit on the branch — 975 on develop the day this landed), `commit` = the short sha (what makes the number unique), `branch` (`null` on a detached HEAD — a CI checkout of a tag or a PR merge ref — never the literal `HEAD`), `dirty` = `status --porcelain` non-empty (uncommitted **or untracked** files), `date` = the commit's ISO date, `shallow` = `rev-parse --is-shallow-repository`; `source: 'git'`. A shallow clone (`git clone --depth 1`, actions/checkout's default) has no history to count, so `build` is `null` there rather than the clone depth. Four git spawns per read (rev-parse answers the top-level directory, the shallow flag and the branch at once; `log -1 --format=%h%n%cI` the sha and the date), every one guarded (no binary, no repo, or a git-less copy sitting inside somebody else's repo — `--show-toplevel` must be this tree), falling back to a `build.json` stamp at the root (`source: 'file'`; a stamped build number must be a non-negative safe integer, anything else reads `null`), then to package.json alone (`build: null`, `source: 'package'`). Memoised per root; `refresh: true` re-reads. `buildLabel(info)` → `v0.4.0 · build 975 · 9c4f827 · develop` (`· dirty` appended; `build unknown` followed by whatever is known — `v0.4.0 · build unknown · 9c4f827 · develop · shallow` on a shallow clone, `v0.4.0 · build unknown` from package.json alone), `buildShortLabel` → `v0.4.0 · build 975`. Node-only (child_process), so it lives under `server/`: `tools/lib/` is served to the browser at `/lib` and must stay free of `node:*` imports; the CLI and the stamp tool import it as `../server/build-info.mjs`.
- **`npm run build:stamp`** (`tools/stamp-build.mjs`) writes the git-ignored `build.json` for a tree that will be copied without `.git` — a tarball, a container. A checkout with history is stamped (exit 0); a shallow clone is refused (exit 2, naming the fix: `fetch-depth: 0`, `git fetch --unshallow`) and a `build.json` lying there is removed rather than copied into an image; a git-less copy that already carries a readable stamp keeps it (exit 0, `kept existing build.json: …` — the file is the copy's identity); a git-less copy without one has nothing to stamp (exit 2; an unreadable `build.json` is removed). `--root` needs a directory with a package.json, and unknown arguments are refused (exit 3), so a typo never stamps the wrong tree. The Dockerfile copies `build.json*` next to package.json and says to stamp before `docker build`; its `OBSERVOGRAM_BUILD` ARG no longer defaults to `container` and now overrides `/healthz`'s composite string only. The image also creates `/app/.observogram` for the `node` user it runs as — the documented `docker run` had died with `EACCES` while seeding the admin user, since before this branch — and the run line carries the `OBSERVOGRAM_ADMIN_PASSWORD` the server needs to start off loopback; the k8s README and the kustomization comment gained the stamp step.
- **`GET /api/version`** — the fields plus `label`, public (registered before the auth and tenancy middlewares: the footer fills before anyone signs in, and it holds nothing secret; the README's Security Posture names it as one of the two routes readable without a session), `Cache-Control: no-store` so a proxy never pins an old build to a new process. `/healthz` keeps its `build: "975.9c4f827+dirty"` composite, now derived from the same reader (`server/version.mjs`, resolved on first use rather than at import), so a worktree no longer reads `untracked`.
- **Studio** — the footer's `<span id="build-label">` ships package.json's version as its fallback and `studio/build-label.mjs` fills it at boot following docs/UI_CONVENTIONS.md: loaders `loadBuildInfo` and `loadHealth` (fetchFn injectable) → `buildLabelModel` (pure) → `renderBuildLabel` (the span) and `renderVersionChrome` (the span, the Advanced menu's About entry, the header subtitle in the short form, the brand tooltip); `loadVersion()` in app.mjs is only their composition. The title is the ISO date + `source: git | file | package` (+ `shallow clone: no history to count`); on a failed fetch the fallback stays. `loadVersion()` is called from `boot()` again — the call was lost in the merge that landed About (1b63b35), which is why the About entry always read "version unknown" — and the About modal now shows commit · branch · dirty, the commit date, the source and, on a shallow clone, that there is no count. `app.css`'s header drops its stale `v0.3`.
- **`packc --version`** prints the label (the version stays the first token; `--version --json` prints the fields), and the help banner carries it on its first line.
- **Tests** — `tools/test-build-info.mjs` (a throwaway repo with three commits reads build 3 with git's sha and branch, a fourth uncommitted file flips dirty, a nested git-less copy borrows nothing, a `--depth 1` clone reads shallow with `build: null` and is refused by the stamp, a detached HEAD reads no branch, the stamp round-trips through a copy without `.git` and survives a re-run there, a stamped build number outside the non-negative safe integers reads `null`, `--root` without a value / without a package.json / with an unknown argument exits 3, package-only reads `build: null`, the labels, the memo and `refresh`, the studio loaders, model and both renderers headlessly, the footer fallback === package.json version); the smoke suite covers `/api/version` (200, JSON, no-store, the fields, agreement with `/healthz` — on a shallow checkout by the sha alone — and the served shell's span) and clears `OBSERVOGRAM_BUILD` so a shell export cannot change what it asserts; the identity suite asserts `/api/version` answers 200 without a session in both the stand-alone and the seeded posture.

### Dashboards: symmetric generated boards — full rows, equal heights, balanced tiles, bound-SLO bar gauges
`flow()` still lays panels out in reading order, but what the generator hands it now always closes every row: on the committed boards a source board with one bound SLI put a w4 tile, the w12 bar gauge and one w6 burn curve on a row, wrapped the second curve alone underneath and left a hole under the tile (`kafka-consumer-lag`, `grafana-alerting-health`); with two SLIs the tiles and the bar gauge filled 20 columns and both curves wrapped to a half row (`grafana-plugins-and-auth`, `prometheus-query-engine`, `prometheus-tsdb-health`); one derived view rendered at w12; a pack with 5 or 7 SLIs left a 4- or 3-column hole in the unified tile row; a burn-template board's w4 tiles wrapped 6 + 2 for 8 SLOs; and the bar gauge on a bound board listed every SLO of the pack. Every visual row of every board the generator emits is now 24 columns wide with one height (`tools/lib/dashboards/lib.mjs`, `generic.mjs`):
- **Tiles** (`splitWidths(n)`, `tileRows(n)` in lib): a row of n tiles takes widths that sum to 24 and differ by at most one, the remainder on the first tiles — 5 → 5,5,5,5,4; 7 → 4,4,4,3,3,3,3; 6 → 4×6; 8 → 3×8. More than eight take the fewest rows of at most eight, the larger rows first (9 → 5,5,5,5,4 over 6,6,6,6; 13 → 7 + 6; 25 → 7 + 6 + 6 + 6), so no tile is ever narrower than w3 (a single row of 12 would have been twelve w2 stats). A lone tile is not stretched to w24 (a banner-wide number with a sparkline): it sits w6 h8 beside its own trend — `derivedSliTrend`, the SLI over time with the objective or threshold as a dashed line — or, on a burn-template board, beside the alert timeline. Two tiles share the row at w12. The unified board's SLI tiles, a source board's and a burn-template board's SLO tiles (`burnTiles`, 8 SLOs → 8 × w3 on one row) all follow this; `derivedSliTiles` takes `widths` (per tile) and `h` besides `w`. A pack module's `sliTiles(pack, ids, { widths, h })` receives the same hint; tiles that ignore it are laid out as the module returns them, on their own row above the standard bar gauge and curves (never inside the one- or two-tile shapes that assume w6 h8 tiles).
- **The contract block** — the unified board's (every SLI and SLO) and a source board's (what it binds, each id once, only ids the pack declares) — by the number of SLIs N and SLOs M it holds (`contractBlock`): M = 0 the tiles only; N = 0 the bar gauge w12 with the two burn curves w6; N = 1, M = 1 the tile, the SLO's burn tile and the two curves, all w6 h8 on one row (a one-bar gauge has nothing to compare with and sat mostly empty in an h8 panel); N = 1, M ≥ 2 the tile w6 h8 beside the bar gauge w18, the curves w12 on the next row; N = 2 both tiles w6 h8 beside the bar gauge w12, the curves w12 below; N ≥ 3 tile rows of their own, then the bar gauge w12 with the curves w6. A burn-template board with a single SLO shows its burn tile w6 h8 beside the alert timeline w18 and no bar gauge.
- **`burnBars(binds, w, h, sloIds)`** filters the series to the SLOs a board holds (`{slo=~"a|b"}`); when `sloIds` names every SLO of the pack, matches none of them (a burn board with `params.slos: []`, a source board whose only SLO binding is a typo) or is not given, the expression is the bare series as before, so no board ever carries the empty selector `{slo=~""}`. The overrides (label and thresholds per SLO) already followed the bound list; only the expression changed. The unified boards' bar gauge is unchanged and the MQ pack's module-built boards (`burnBars(null)`, `burnBars(all, 12, 8)`) are byte-identical.
- **Derived views** (`viewWidths(n)`, `derivedViewPanel(..., { w })`): 1 → 24; 2 → 12,12; 3 → 8,8,8; four or more in pairs of 12, an odd count closing with a trio of 8. On the unified Signals row and a source board's §5 row the views that render as graphs come first; a note (an undeclared view, or one with neither a metric nor a declared SLI, such as the golden-signals views) is w24 on a row of its own below them. The per-resource template board renders its view at w24. A view on a trio row is w8, below the width at which `ts()` switches a many-series graph to the right-hand table legend with last/max, so it gets the bottom list legend; on a full or half row the table legend as before.
- **Bar gauges with few bars pin their text** (`tools/lib/dashboards/lib.mjs` `bargauge` takes `text`; `burnBars` sets `{ titleSize: 16, valueSize: 28 }` when it shows three bars or fewer): Grafana scales a bar gauge's name and value with the panel height, and the two-SLO gauge of a bound board rendered 60 px truncated names once it stood alone on an 8-high row. A gauge of every SLO is unchanged.
- **`checkBindings`** now reports a source-board binding or a burn board's `params.slos` entry that names no SLI or SLO of the pack (`binding slos.nope names no SLO of the pack`) instead of letting it shape the block or filter the bar gauge to nothing.
- **Goldens regenerated** with the generator's own commands (`node tools/gen-dashboards.mjs --pack reference-packs/<p>.pack.yaml`, `node tools/test-golden-compile.mjs --update`), no hand edits. ## 0.4.0 — 2026-09-20

**The monitor-of-monitors release.** Observogram assures that the artefacts which monitor a system keep doing their job: the live fetcher stops asserting what it never observed (steps 0-1), the stack samples its own self-metrics through the MCP (step 2), journeys keep stack-health evidence per run (step 3), and the requirement graph shows what would go blind when an artefact dies, a per-node ladder and candidate causes (step 4). The pack generators (boards including a Unified Observability board for every pack, burn-rate rules with the live-measured PromQL, gen-site for a fleet of environments from one pack and an inventory) became one vendorable library and the compiler emits the same PromQL. Also: stage 2 tenancy, first-boot admin and account menu, Diagnose views on the behavioural engine, the Tomograph to Observogram rebrand, legacy pack format support.

### Blind-spot blast radius on the graph (step 4)
Step 3 kept the stack's own self-metrics per journey run; step 4 puts the **monitor-of-monitors question on the requirement graph itself**: what would go blind if an artefact died (structural exposure), whether a present artefact is doing its job or the vantage could not look at all (the per-node ladder), what changed since the previous run, and which candidate causes the evidence can offer. Three things are true of everything in this block, by contract and pinned by the suites: **nothing scored changed** — `branch.integrity` / `verdict` / `counts`, every node `status`, `rollup.integrityMean` and the grade's Drift-free criterion are byte-identical with and without the new annotations, everything new is an additive field beside them, and the switch to the ladder is a proposal (`docs/SCORING_PROPOSAL_LADDER_INTEGRITY.md`), not applied; **the honesty vocabulary is kept** — a blast radius says what WOULD go blind, never that something IS blind, `unobserved` means the vantage could not look (a probe family failed or is not exposed by the tier), never "absent", and `present_unhealthy` means on the wire but not doing its job; and **causes are candidate causes ranked by evidence — not a root-cause verdict**, with a change of the vantage itself reported separately and never as a cause. No new MCP tool name, no new dependency, no build step; the two new reasoning modules are zero-import and vendorable.
- **Blast radius (reverse index).** New zero-import `tools/lib/blast-radius.mjs`: `CONSUMER_SIDE` (per edge type, which side consumes the other's assurance — `from` for `sli_of`, `sources`, `exported_by`, `produced_by`, `protects`, `forecasts`, `visualises`, `contains`, `routes`, `remediates`, `validates`; `to` for `materialises`, where the SLI consumes the rule's series), `PROTECTION_SIDE` (the `to` side loses when the `from` side dies: an SLO loses protection with its alert, an alert loses delivery with its route and remediation with its remediation — transitive, a dead route means an undelivered alert means an unprotected SLO), `normalizeGraphShape` (nodes as an array, a Map or a keyed object; edges without `from` / `to` / `type` dropped; edge types outside the table carry no known direction and are ignored), `blastRadiusOf(shape, key, { weights })` → `{ key, kind, label, blinded: { total, weight, byKind, nodes: [{ key, kind, label, hop }] }, unprotected: { slos, alerts }, summary: { slos, alerts, panels, dashboards, routes, remediations, total } }` (`null` for an unknown key; breadth-first over the reverse adjacency, cycle-safe; `blinded.nodes` sorted hop → `KIND_ORDER` → label and capped at `BLINDED_NODES_CAP` = 64 while `total` / `byKind` stay uncapped; protection losers already blinded are not listed twice; `weight` sums `DEFAULT_WEIGHTS`, a copy of the graph's limb weights, unknown kind 0.5) and `blastRadiusIndex(shape)` → `Map key → summary` in sorted key order. Scaffold placeholders (a `scaffold` flag or `artefact.source === 'Scaffold'`) never blind anything, are never traversed and are never listed. `traceability-graph.mjs` exports `graphShape(graph)` — the artefact-free projection `{ nodes: [{ key, identityKey, kind, layer, label, virtual, scaffold }], edges: [{ key, from, to, type, provenance }] }` — and `compareBranches` computes the A-graph and B-graph indexes once per comparison, attaching `blastRadius: summary | null` to every node verdict (A's index for aligned / drifted / declared-only / unverifiable nodes, B's for live-only ones).
- **Per-node ladder (additive, unscored) + the scoring proposal.** Every node verdict gains `ladder: { rung, status, detail }` — rungs `unobserved < absent < exists < alive < healthy`, status `present_unhealthy` | `present_stale` | `unobserved` | `null` — read from what the live fetcher wrote into Pack B: `mcp.observed.scrape_targets` / `recording_rules` / `alert_rules`, the `mcp.discovered.scrape_jobs_down` / `recording_rules_unhealthy` / `alert_rules_unhealthy` / `slis_unhealthy` lists, `mcp.probesFailed` / `mcp.probesUnsupported` with `mcp.probeErrors.<family>`, `mcp.versions.<product>` for backends and `mcp.refreshedAt` as "now" (a timestamp older than 2× the artefact's interval reads `present_stale`; no interval or no timestamp means staleness is not judged). Burn-rate alerts link to live alert rules by the compiler's `<slo>_burn_<factor>x_<short>_<long>` convention, narrowed to the declared windows. ### Stack self-metrics (step 2)
Observogram monitors the artefacts that monitor the system; step 2 of the roadmap starts **acquiring the observability stack's own health signals** through the MCP so later steps can build stack-health evidence and early warning. Three things are true of everything in this block, by contract and pinned by the suites: **every sampled number is a point-in-time signal, not a verdict** — no `Verified` stamp, no `Scaffold` marker, no SLO verdict and no grade criterion or grade input changed anywhere; **a restricted MCP tier reads `not-attempted` with the reason**, never "absent"; and **the alias table reads only names a real product exposed** — it was documentation-grounded when written (every metric name following the product's upstream docs, named on the row) and now carries three live evidence sources: the pinned Docker stack (`npm run test:stack:live`, every alias stamped with the image it was verified on) and the public (2026-09-07) and authenticated (2026-09-08) Krystaline tiers (`npm run record-fixtures`); a product a given stack does not run reads an honest `not-in-inventory`.

### Live evidence honesty: the fetcher stops asserting what it never observed
The top product risk is false assurance — a live pack reporting `Verified` / aligned / fresh for an artefact that is not doing its job. This entry removes the known false-assurance paths in `tools/fetch-live-pack.mjs`, makes the on-wire liveness signals visible, lets journeys gate on the vantage, and stops two authoring-only differences from reading as drift. **Existing users should expect alignment percentages and grades to drop against the same MCP** — placeholders that used to count as `Verified` now park as `Scaffold`, burn-rate alerts the platform never had no longer align with the ones the repo declares, and scrape jobs whose targets are all down no longer attest scraping. The lower number is the honest one.

**False-assurance fixes**
- **Burn-rate alerts are mapped from discovered rules, never synthesised.** The fetcher used to emit a two-window burn-rate alert for every inferred SLO and stamp `mcp.verified.policy.burn_rate_alerts` whenever *any* alert name came back. `spec.policy.burn_rate_alerts` is now built from the alerting rules the MCP exposes — compiler-labelled rules (`slo`/`burn_rate`/`window_short`/`window_long`/`severity`) and `<slo>_burn_<N>x_<short>_<long>`-named rules, grouped per SLO, deduped, short window first — and each entry gets an **indexed** `mcp.verified.policy.burn_rate_alerts[<i>]` stamp (the unindexed key is gone). A group whose SLO shares the SLI base of an inferred placeholder re-identifies that SLO to the discovered id and replaces its placeholder objective/window from the `slo_objective`/`slo_window` annotations; groups naming an SLO nobody inferred, or carrying a single window, land in `mcp.discovered.alert_rules_unmapped`; forecast rules are skipped; severities outside the `SEVn` enum are mapped from the Prometheus vocabulary or the burn factor and listed in `mcp.discovered.alert_rules_severity_inferred`. When nothing maps, the schema-forced placeholder is stamped `mcp.scaffold.policy.burn_rate_alerts[0]`.
- **Every placeholder the fetcher invents is `Scaffold`, never `Verified`.** `mcp.scaffold.<symbol>` (the live counterpart of `crawler.scaffold.<symbol>`; `tools/lib/adapter.mjs` `sourceOf` now honours both prefixes) marks the hard-coded `spec.otel` block (`system_health` answering used to verify it), collector receivers/processors, the logs/traces exporters, the fallback `logs-elastic` backend, the `platform-overview` dashboard stub, the SEV1 → Teams route, the baselines, and the per-service / `platform_availability` SLI+SLO guesses. `pipelines.exporters.metrics` is `Verified` only when scrape targets or a metric inventory evidenced it; `metrics-prom` only on a `*_build_info` capture; `traces-jaeger` only when the topology names jaeger or `traces_services` answered. SLIs inferred from real recorded rules stay `Verified`; an SLO re-identified by a discovered burn-rate group becomes `Verified`.
- **MTTD is no longer derived from anomaly thresholds.** `spec.baselines.mttd_target_p50` was the smallest `anomalies_baselines` `thresholdMs` (e.g. `90ms`) stamped `Verified` — a latency-anomaly threshold is not a time-to-detect target. Baselines are now the platform default for the declared criticality (`measurement_source: platform-default`, stamped `Scaffold`) until a §5.10 measurement exists; `mcp.baselinesComputed` still counts the anomaly baselines returned, which is evidence the tool answered, not a measurement.

**Liveness evidence (on-wire health)**
- A scrape job NAME used to be enough to stamp `mcp.verified.telemetry.scrape` and `mcp.verified.pipelines.exporters.metrics`, and a rule's presence was enough to verify it, even when the same payload said every target was `down` or the rule was failing to evaluate. The `scrape_configs` probe now adapts to per-job target lists (`[{job, targets:[{instance, health, lastScrape, lastError}]}]`, tolerant of otel-mcp-server's `metrics_targets` and Prometheus `/api/v1/targets`): only jobs with at least one target `up` (or of unknown health) land in `mcp.discovered.scrape_jobs` and attest scraping; jobs whose every target is down go to `mcp.discovered.scrape_jobs_down`; every target's health is kept in `mcp.observed.scrape_targets` (JSON, 200 entries, `lastError` trimmed to 200 chars). When no job is up the metrics exporter falls back to its scaffold marker.
- The `recording_rules` / `alert_rules` adapters carry `health`, `lastError`, `lastEvaluation`, `evaluationTime` (and `state`, `activeAt` for alerting rules); the fetcher strips them before `spec.queries` and writes `mcp.observed.recording_rules` / `mcp.observed.alert_rules` plus `mcp.discovered.recording_rules_unhealthy` / `alert_rules_unhealthy`. Recording rules are stamped **per index** (`mcp.verified.queries.recording_rules[<i>]` — the symbol the adapter actually reads; they used to project `Declared` despite the group stamp) and only when healthy or health-less; a burn-rate group fed by an unhealthy alerting rule still maps but earns no indexed stamp. Absent health is never treated as unhealthy; legacy job-name `string[]` probe results still count as health-less scrape evidence.
- Draft summary (`POST /api/draft-from-mcp`) gains `scrapeJobsDown`, `recordingRulesUnhealthy`, `alertRulesUnhealthy`; the studio lists `N scrape jobs down: …` and `N rules unhealthy: …` when non-empty.

**Probe honesty (what the MCP could and could not answer)**
- A probe family whose every candidate is absent from `tools/list` was recorded as `unsupported` by the probe loop but never emitted; the studio read it as "probed, none found" and warned that the family "returned empty". The pack now stamps `mcp.probesUnsupported` (a restricted MCP tier) beside `mcp.probesFailed` (a hole of unknown size), and `mcp.probeErrors.<family>` carries the last erroring candidate's message (trimmed to 200 chars). `fetchMcp` returns its `probeFailures` map; `buildCanonicalPack` accepts it.
- `partialLiveEvidence` (vendored, zero-import) gains additive keys only: `unsupported`, `errors`, and `vantage` (`full` / `partial` / `restricted` / `lost` / `none`); `partial` keeps meaning outright failures. `GET /api/live-status` returns `probesFailed` and `probesUnsupported`; the MCP badge goes to its error state for failed probe families and names a restricted tier in its title; the draft summary lists unsupported families as "— not exposed by this MCP" (with the probe error inline for failed ones) and warns once about the restricted tier; the partial-evidence banners append the not-exposed families.

**Journeys: studio grade parity, vantage-aware gate, vantage-lost records**
- **One score for one comparison.** `tools/lib/journey.mjs` attaches the requirement-chain comparison (`comparePackBranches`) to the diff as `traceabilityGraph` before grading — exactly what the studio's `/api/diff` does — so the CLI and the studio score Drift-free on the same construct. The run record says which construct scored it (`grade.driftConstruct`: `requirement-chain` / `diff-buckets`) and carries the chain rollup (`traceability`).
- **The vantage is part of the verdict.** Run records gain `probes {attempted, succeeded, empty, failed, unsupported}`, `probeErrors`, `vantage`, `toolsExposedCount`, `scrapeJobsDown` and `unhealthyRules`, read from Pack B's fetcher annotations (a file-sourced B reports empty lists, `0`, `null`, `none`). Two new gate keys: `failOnPartialEvidence: true` breaches when any probe family failed or the vantage is entirely lost; `maxUnhealthy: N` breaches when scrape jobs down + unhealthy rules exceed N. Empty and unsupported families never breach on their own. The markdown report prints `Live probes` and `On-wire health` lines; the README gate example shows both keys.
- **Vantage loss is a point in history, not a hole.** When Pack B is an `mcp:` source and the fetch itself fails, the journey writes an `outcome: vantage-lost` record (error, both sources, timing, no fabricated grade) before rethrowing — exit code stays `2`, the studio route still answers 502. Configuration errors (missing file, unset `authEnv`) leave no record. `packc journey list` and the studio Journeys view render the outcome without a fake `alignment undefined%`.

**Canon: two authoring-only differences stop reading as drift**
- `tools/lib/promql-canon.mjs` removes the spaces around the symbolic binary operators `+ * / % ^ == != <= >= < > =~ !~` (outside strings, parser-proven expressions only), so `a / b` ≡ `a/b` and `rate(x[5m]) > 0.5` ≡ `rate(x[5m])>0.5`. `-` is left alone (unary/binary ambiguity), keyword operators keep the space that bounds them, label-value strings stay byte-identical, and a space *inside* an operator (`a < = b`) is never glued into a different one. Decision-bearing differences (`>` vs `>=`, thresholds, `=~` vs `!~`) still read as drift.
- `tools/lib/artefact-model.mjs` `behaviorFor` strips a leading `ref:` from `slo`, `sli`, `trigger`, `error_budget_policy`, and from `expr` when the whole value is a reference (`ref:slis.x`), via a pure `stripRefFields` copy of the spec — identity already stripped it, so a burn alert declared `slo: ref:x` paired with the live `slo: x` and then reported itself drifted on its own binding. Both modules are vendored downstream (`docs/VENDORING.md`): additive behaviour only, no new imports, signatures unchanged — re-copy the pair together.

**Review follow-ups (false-assurance re-audit)**
- **Placeholders never pair.** The studio construct (`diffPacks` + `comparePackBranches`, which the journey now grades on) still paired a live `Scaffold` placeholder with a declared artefact: a declared burn-rate alert on the live pack's first SLO read `aligned` when it carried the compiler's default windows (exactly the placeholder's) or `drifted` otherwise — never `declared, not live` — and BAK-01 / PIP-PRC-01/02 / the SEV1 route aligned or drifted against scaffold backends, processors and the fallback route. Only the diff-bucket grade path parked them. `diffPacks` now removes `source: Scaffold` artefacts from both sides before pairing into a new `scaffold` bucket (`summary.scaffold`; a repo placeholder is not a declaration either, so a real live route the repo only had a placeholder for reads `live, not declared`); `comparePackBranches` refuses a `Scaffold` live node as evidence (`declared_only`), never emits it as `live_only`, drops a live-only branch rooted on a scaffold SLO, and does not count a scaffold route/dashboard as proof the live connector can see that kind. Journey facts (`alignmentPct`, `aligned`, `declaredNotLive` → `maxDeclaredNotLive`) follow; the run record carries `drift.scaffold`. The studio drift drill, verdict and prototype views read the new bucket beside the older `isScaffoldDiffEntry` filter.
- **Tiered SLOs on one SLI no longer produce a dangling ref.** `mapDiscoveredBurnAlerts` resolved groups in one pass and only tracked re-id candidates as claimed, so an `x_99_9` group could re-identify the SLO an `x_99` group had already bound exactly — `spec.slos` then held `x_99_9` while `burn_rate_alerts[0].slo` still said `x_99` (POL-01 Verified with a ref pointing at nothing; the schema's pattern-only `Ref` never caught it). Exact matches now bind and claim first; base matches re-identify only unclaimed placeholders; the leftover group is reported in `mcp.discovered.alert_rules_unmapped`. Exact matches apply the `slo_objective`/`slo_window` evidence and drop the SLO's scaffold marker like a re-id does; a re-id to an id that is not a schema Slug (length included) is refused.
- **Health follows the evidence down the chain.** An SLI inferred from recorded rules of which one is reported unhealthy is no longer stamped `mcp.verified.slis.<id>` (new `mcp.discovered.slis_unhealthy`); an SLO bound by a burn group fed by an unhealthy rule is not stamped either; rule health is keyed by name with any-unhealthy-wins semantics (a duplicated name reported `err` in one group and `ok` in another stamped both spec entries Verified while being named unhealthy); the requirement traceability chain lists an unhealthy live alerting rule with `verified: false` / `health: err`, does not let it (or a scaffold burn-rate entry) close `missing_alert_evidence`, and counts `withAlerts` on evidence only — the studio chain rows and the requirement-trace drawer show `(unhealthy)`.
- **Under-reporting fixed too.** Discovered dashboards are stamped per id (`mcp.verified.dashboards.<id>`, the symbol the adapter reads) beside the aggregate key, so they project `Verified` instead of `Declared`. `mcp.probeErrors.<family>` is written only for families whose outcome is `failed` — a family whose later candidate answered no longer carries the earlier candidate's error while sitting in `probesSucceeded`.
- **Fresh names the vantage.** The grade's Fresh criterion keeps its staleness pass/fail (scoring is out of scope) but its detail now says `vantage lost: no probe family answered (failed: …; not exposed: …)` or `vantage partial: failed …`, so a refresh that saw nothing does not read as a fresh look at production. `.journey-outcome.is-lost` uses a new `--warn` text token instead of a hard-coded colour.

**Fixtures re-pinned** (`npm run test:contracts:update`): `tools/fixtures/mcp/adapted/scrape_configs.json` is now per-job target health instead of a job-name `string[]` (the `alertmanager` job is present with its `down` target and `lastError`); `recording_rules.json` / `alert_rules.json` carry the observation fields (`health`, `lastError`, `lastEvaluation`, `evaluationTime`, and `state` / `activeAt`). No crawler or compiler golden changed.

**Suites**: `tools/test-fetch-live.mjs` (placeholder + mapping paths, every scaffold key and its adapter projection, the excluded down job / all-down / legacy / adapter-shape cases, per-index rule stamps, the unsupported/failed split and per-family error mapping), `tools/test-diagnostic-grade.mjs` (every vantage), `server/test-smoke.mjs` (live-status fields on a planted live pack), `tools/test-journey.mjs` (both gate keys, record fields, studio parity, the vantage-lost record via a closed loopback port, the no-record rule), `tools/test-promql-canon.mjs` and `tools/test-diff.mjs` (operators, fences, `ref:` ≡ bare). ### Studio Diagnose views rejoin the behavioural engine
- **Diagnose → Compare cards classify from the diff again.** The side-by-side view derived its in-both / only-in chips by recomputing keys client-side as `defines || id` — a lossy approximation of the old diff keyspace that stopped matching entirely once the engine moved to behavioural identity keys (`kind::{identity}`): the summary band said N matched while all cards below rendered unclassified and the "In both" / "A − B" slice filters returned nonsense. Cards and slice filters now classify by the artefact ids embedded in the diff entries themselves (unique per pack side) — no client-side key math to drift again.
- **Traceability (Advanced) is diff-driven.** Its repo-vs-live buckets were re-derived locally by raw id match + whole-object JSON equality (only `annotations`/`_sub` stripped), so behaviourally-identical artefacts with different ids double-counted as declared-not-verified *and* verified-not-declared, and endpoint/expression-formatting differences flagged Stale. The four buckets now re-bin the server diff — aligned = inBoth-aligned, stale = inBoth-drifted (with the engine's delta fields named on each row) — and reconcile with the drift drill's **unlensed** totals: out-of-scope artefacts and scaffold placeholders are parked the same way (counts + live-scope control shown), while the drill additionally applies the active product lens. Panels stay compared at dashboard granularity (the engine's rule), now stated in the view. The view fetches the diff itself when it isn't loaded yet. Suppress/resolve prefs now key on behavioural identity keys (collision entries append the artefact symbol so `#NN` ordinal reshuffles don't migrate a suppression), so previously-saved entries no longer match and reset once.
- **Stale-diff hardening.** `state.diff` is stamped with the selection it was computed for (`packs + envs + scope + service`) and every consumer treats a mismatch as *no diff*, refetching instead of rendering — previously a Pack A/env switch could leave the views classifying the new pack against the old diff's positional ids. Late responses for a superseded selection are discarded, concurrent renders share one in-flight fetch, and the three loading branches only re-render on progress (an unregistered Pack A now gets an honest error instead of a render loop).
- `prettyDiffKey` learned the behavioural keyspace (`kind::{identity-json}` with `#NN` occurrence ordinals) — backend, pipeline-stage, storage, mesh/collection, product-keyed, scrape-job, imports, and remediation identities render as readable labels instead of raw JSON, and forecast alerts are no longer mislabelled as burn-rate alerts.

### Account menu: profile, change password, sign out
- The identity chip in the studio header is now an **account menu**: who you're signed in as (and the auth mode), **change password…** (stand-alone mode — OIDC passwords belong to the IdP), and **sign out**. It renders in identity postures only; the open posture (`OBSERVOGRAM_AUTH=off` or no users file) has no accounts to manage.
- **Signed-in users can finally change their password**: `/auth/change-password` now also accepts a session. The current password is required — that knowledge is the CSRF defence — and wrong guesses share the login damper (5 failures → 30s lockout). The mid-login forced-change flow (flow cookie, skip) is behaviourally preserved, with one deliberate alignment: a user deleted mid-flow now gets "unknown user" before password validation, matching the session path.
- **Login now clears a leftover pwchange flow cookie.** An abandoned forced change (admin/admin typed on a shared browser, then closed) used to leave a 10-minute flow cookie that shadowed the session on `/auth/change-password` — the account menu's link could silently target the *other* account. A normal login expires it.
- Known limitation (stateless sessions, pre-existing model): rotating a password does **not** revoke other outstanding sessions — an already-stolen cookie rides out its TTL (default 8h). Real revocation needs a per-user epoch in `users.json` checked at session verification.
- Suite: 15 new assertions in `server/test-auth-local.mjs` — the session variant of the page (current-password field, no skip control; the flow variant is pinned to *lack* the field), wrong-current 401 in JSON and HTML, short-replacement 400, rotation in JSON and HTML (302 home), old password dead / new signs in, deleted-user GET/POST with a live session, the stale-flow-cookie clear on login, the 429 lockout, and the damper being shared with `/auth/login`.

### "Skip for now" on the forced password change
- The first-boot change-password page now offers **Skip for now — ask again next sign-in**: a session is issued without replacing `admin/admin`, the forced-change flags stay set, and every subsequent sign-in re-prompts. New `POST /auth/change-password/skip`, credentialed by the same signed flow cookie as the change itself.
- **Deliberately narrow**: skipping works only while the record still holds the *seeded default* — an admin-set temporary password (`mustChange` without `seededDefault`) stays a forced change, and the loopback guard is unaffected (a skipped default still refuses to bind beyond loopback).

### Ships like Grafana: default admin on first boot
- **First boot with nothing configured now seeds a default `admin` user (password `admin`)** and the login page is live — the studio is a signed-in app out of the box, no CLI setup. The password change is **forced at first sign-in** (new `/auth/change-password`, signed short-lived flow cookie, no session until the change lands). _Softened later in this release: skippable per session for the seeded default — see the "Skip for now" entry above._
- **The default credential never crosses loopback**: a network boot never seeds `admin/admin` (it refuses to start and names the options), and `start()` refuses to bind beyond loopback while an already-seeded default is unchanged. Container/network boots set `OBSERVOGRAM_ADMIN_PASSWORD=<secret>` to seed a real credential (no forced change); the same env var also *replaces* a still-default admin record, so a workspace seeded on loopback can be moved behind the network without a deadlock.
- The seed backs off from any expressed intent: OIDC configured, an existing users file, `OBSERVOGRAM_API_TOKEN` (the token-only 10B contract is unchanged), or armed tenancy.
- **New `OBSERVOGRAM_AUTH=off`** — the one switch that disables identity entirely (no login, no seeding, `/auth/*` answers 404): the pre-0.5 open posture, kept for dev shells, scripts and CI. This is a **default-behaviour change**: `npm start` on a fresh workspace now lands on a login page.
- Stand-alone auth arming is now per-request (routes register once, posture follows the users file), so the seed at `start()` and `npm run users` both take effect without a re-import; `npm run users -- passwd` clears a pending forced-change flag.
- Suite: `server/test-auth-local.mjs` grew 18 assertions — seed shape, 401-by-default, loopback guard, the full forced-change flow, `OBSERVOGRAM_ADMIN_PASSWORD` (fresh seed + rescue), never-seed-on-network-boot, and the off switch; `server/test-smoke.mjs` runs under `OBSERVOGRAM_AUTH=off` and is the open-posture regression.

  - Env vars: every knob reads `OBSERVOGRAM_*` first, then the legacy `TOMOGRAPH_*` (`WORKSPACE`, `API_TOKEN[_LABEL]`, `OIDC_*`, `SESSION_*`, `USERS_FILE`, `INSECURE_NO_AUTH`, `ALLOW_LOCAL_MCP`, `STRICT_SNAPSHOT`, `BUILD`, `DEBUG`, `DIFF_SCOPE`, `MCP_TIMEOUT_MS`, `GRAFANA_*`).
  - Workspace: the default directory is `.observogram/`, but an existing `.tomograph/` keeps being used as-is (no migration needed, no data orphaned).
  - HTTP: the studio sends `X-Observogram-Org` / `X-Observogram-CSRF`; the server accepts the `X-Tomograph-*` spellings too and echoes `X-Observogram-Org`.
  - Sessions: the cookie is `observogram_session`; sessions issued pre-rebrand under `tomo_session` stay valid (same HMAC secret), and logout clears both.
  - Pack annotations: writers emit `observogram.*` (`diff.scopeMode`, `retrofeed.*`, `services`); readers accept the `tomograph.*` namespace from pre-rebrand packs, new key wins when both exist.
- Legacy-compat is CI-asserted (workspace env fallback, org/CSRF headers, session cookie, annotation namespace).

### Vendorable verdict engines (downstream-studio decoupling)
- `studio/diagnostic-grade.mjs` is now **zero-dependency** (`L4_SUBGROUPS` inlined) — vendorable verbatim, like `tools/lib/diff.mjs` and `tools/lib/protocols.mjs`.
- `studio/verdict-ui.mjs` no longer reads global state: `buildVerdictModel()` / `projectGrade()` take `{ pack, packB, diff, compareBId, catalogEntry }` explicitly and `loadRunHistory()` accepts an injectable `fetchFn`.
- New `studio/compare-catalog.mjs` — `catalogEntryFor()` + `LAYERS_FOR_DIFF` extracted from the 3000-line compare-view (which re-exports them), so verdict modules import the small catalog module instead of the whole view.
- See the new [docs/VENDORING.md](VENDORING.md) for the downstream contract.

### The studio host seam (no view imports app.mjs for orchestration)
- New `studio/host.mjs` — a zero-import module holding the app-level callbacks (`loadPackB`, `openDeployModal`, `renderMainView`, `renderTabs`); app.mjs fills it once at boot via `initHost()`. Every view module (compare, compile, layers, drawer, journeys, references, atlas, all protos) now calls these through `host` (imported as `appHost`) instead of importing app.mjs — app-specific *helpers* remain direct imports until each view adopts the model-passing convention.
- New `tools/test-studio-graph.mjs` in `npm test` — links the entire studio ES-module graph headlessly, so a dangling import/export anywhere in the studio fails CI (node --check is parse-only and cannot catch it).
- New `studio/verdict-ui.css` — the `.mc-*` widget styles verdict-ui.mjs emits, split out of app.css along the vendoring seam (the file header documents the theme variables it expects).
- New [docs/UI_CONVENTIONS.md](UI_CONVENTIONS.md) — the adopt-on-touch conventions: host seam, loader/renderer split with injectable `fetchFn`, `render(container, model, host)` signature, and per-zone CSS prefixes.
- Rebrand follow-through: the last "tomogram" vocabulary is now "observogram" (Discover's scan title/tagline, hero-asset path `assets/observogram-hero.png`, docs).

### Fixed: comparing legacy imports (and any cross-service packs)
- The PACK B picker filtered out every pack whose service didn't match the active one — two legacy imports (each deriving its own service from the old pack id) could never be compared. Cross-service packs are now selectable under an "other services" group; same-service packs and live aggregates still lead the list, and the diff's service scope keeps cross-service comparisons honest.

### Stage 2 tenancy — workspace-per-org
- New `server/tenancy.mjs`: org registry in `<workspace>/orgs.json` (the file existing arms tenancy, mirroring `users.json`), per-request org context via AsyncLocalStorage, idempotent flat → `orgs/default/` boot migration. Requires identity; refuses to boot otherwise (fail-closed).
- `workspaceRoot()` is context-aware: registry, deploys, snapshots, journeys, runs all answer from `<workspace>/orgs/<orgId>/` inside a request. The in-memory upload registry and workspace index cache are keyed per org.
- Org selection via `X-Observogram-Org` (default: first membership); membership enforced in middleware; bearer token = deployment-level service account. New `GET /api/orgs`; `/auth/me` carries memberships; roles recorded for Stage 3 (not yet enforced).
- New CLI `npm run orgs -- create|remove|add-member|remove-member|list`.
- Studio: active org resolved before the first catalog fetch; ORG chip (switcher when multi-org) in the OBSERVA bar.
- New suite `server/test-tenancy.mjs` — the isolation gate: org B reads/writes nothing of org A (API + filesystem-path assertions), migration, per-org reset, fail-closed posture.

### Previous pack format (layered JSON) supported again
- New `tools/lib/legacy.mjs` — detects the pre-v1.2 layered "studio-shape" JSON and upconverts it to a canonical v1.2 manifest. Lossless (every legacy artefact kept verbatim in `legacy.artefact.*` annotations), honest (every schema-forced placeholder marked `crawler.scaffold.*` → projects as Scaffold, never Declared), deterministic.
- `POST /api/validate` upconverts legacy uploads transparently; the studio toast reports the conversion (`N artefacts mapped, M scaffolds`).
- New CLI `npm run upconvert-legacy <file> [-o out.pack.json]`.
- The four original layered JSON packs restored from git history as working examples: `examples/legacy/` (+ README documenting the format).
- New suite `tools/test-legacy-pack.mjs` gates all four examples on every `npm test`; the validator's gatekeeper error now points legacy packs at the converter.

## 0.3.0 — 2026-06-08

**The spec v1.2 migration.** Studio now reads, renders, validates, scores, and lives on the canonical [ObservabilityPack spec v1.2](https://github.com/MoebiusX/otel-observability-pack/blob/main/spec/ObservabilityPack-Spec.md). All studio-shape v0.1/v0.2 artefacts are gone.

### Phase 0 — vendored spec
- New `vendor/observability-pack-spec/v1.2/` with the upstream schema, spec, maturity rubric, and worked example, each checksumed into `VERSIONS.json`.
- New `tools/sync-spec.mjs` — refresh + `--check` drift detection (zero deps, uses `gh` CLI).
- Deleted the old `schema/pack.schema.json` (studio-original display schema replaced by the canonical one).

### Phase 1 — canonical-only validator
- Rewrote `tools/validate-pack.mjs` against the vendored canonical schema.
- Gatekeeper rejects pre-1.2 input with a migration-pointer error.
- Extended the JSON Schema 2020-12 walker to cover `const`, `allOf` / `oneOf` / `anyOf`, `if`/`then`/`else`, `contains`, `propertyNames`, `min/maxProperties`, `exclusiveMin/Max`, `format: uri | date-time`, `patternProperties`.
- New `tools/lib/mini-yaml.mjs` — minimal browser-friendly YAML reader.

### Phase 2 — canonical → layered adapter
- New `tools/lib/adapter.mjs` — pure ESM, no Node APIs. Exports `adapt()`, `listEnvironments()`, `applyEnvironmentOverlay()`.
- Maps every spec section to a deterministic family of layered artefacts with `defines` / `refs` for cross-reference checking.
- Environment overlay: deep-clone + dotted-path overrides + effective `target` / `criticality` / `backendWiring`.
- New CLI `node tools/adapt-spec-pack.mjs <pack.yaml> [--env <name>] [--pretty]`.

### Phase 3a — Express + thin client refresh
- **Architectural shift:** the 5,310-line single-file HTML monolith is gone. The studio now ships as:
  - `server/index.mjs` — Express 5 server with a JSON API.
  - `studio/{index.html, app.css, app.mjs}` — thin client that fetches `/api/packs/:id` and renders.
- First runtime npm dep: `express`.
- New visual identity: hairline grid, monospaced data, layer-numbered tabs (L1, L2, L2X, L3, L4 with sub-tabs, L5, GOV), slide-in drawer.
- API: `GET /healthz`, `/api/packs`, `/api/packs/:id?env=<name>`, `/api/packs/:id/canonical?env=<name>`, `POST /api/validate`.
- The four atlases (Stratigraphy, Periodic Table, Constellation, Skyline) and the old source-tag taxonomy (BAU / SLA / NEW / GAP / PLANNED / LIVE) are retired.
- `pages.yml` disabled — Pages can't host a server-backed studio without a build target.

### Phase 3b — UI enrichment + conformance
- Shared `tools/lib/validator.mjs` — CLI + server both import it; ~150 LoC of duplication removed.
- New `tools/lib/conformance.mjs` — 29 hand-curated rubric clauses from spec §5 + §7. Tier-aware scoring (MUST = 1, SHOULD = 0.5; cumulative tier-3 → tier-2 → tier-1).
- New API: `GET /api/packs/:id/conformance?env=<name>`, `GET /api/maturity-rubric`. `POST /api/validate` now also returns `.conformance`.

- Version-gating chips (off / warn / enforce) on backend cards.
- Conformance tab with headline + per-dimension grid + full clause list.
- File-upload + drag-and-drop loader (drops to `POST /api/validate`).

### Phase 4 — canonical-only fetcher
